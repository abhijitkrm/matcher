# Contributing

This is the **specification repo** — the contract that keeps every
implementation honest. Implementations live in
[matcher-rust](https://github.com/abhijitkrm/matcher-rust),
[matcher-go](https://github.com/abhijitkrm/matcher-go),
[matcher-cpp](https://github.com/abhijitkrm/matcher-cpp) and vendor a copy of
`spec/` + `vectors/`.

## The spec-first workflow

1. **Semantics changes** start in `spec/SPEC.md`, then get a golden vector
   (`vectors/**.cmd.jsonl`) plus its canonical `.evt.jsonl` (generated by the
   reference implementation and audited by hand).
2. The change lands in every impl repo, which re-vendors `spec/` + `vectors/`
   and must emit byte-identical event streams.
3. Ports are ports — no language-specific behavior.

## Verify

```bash
# with the impl repos checked out as siblings:
./scripts/verify.sh    # rust + go + cpp golden suites
```

## Golden vectors

- `vectors/manifest.json` lists every vector with its index mode
  (`ladder`, `tree`, or `both`).
- Canonical `.evt.jsonl` files are produced by the reference Rust
  implementation (`matcher-rust`, `REGEN=1 cargo test`) — never hand-edit them;
  audit them.
- New vectors go through the same pipeline: write `.cmd.jsonl`, add to
  manifest, regenerate `.evt.jsonl`, audit, then port the behavior.

## Benchmarks

- Workloads come from `tools/vectorgen` — deterministic, seed-locked.
- Follow `spec/BENCH.md`; report environment (CPU/OS/flags). No unattributed
  numbers in `docs/RESULTS.md`.
